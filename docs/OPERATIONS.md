# Запуск, обновление и обслуживание VORNIXO

[← На главную](../README.md)

## Локальный запуск

Требуется **Node.js 22+**. Установка npm-зависимостей не требуется.

```bash
npm start
```

На Windows можно запустить `START_WINDOWS.bat`. Откройте `http://127.0.0.1:3000`. Для закрытия сервера используйте **Ctrl+C**, чтобы дать приложению сохранить прогресс.

## Доступ в локальной сети

По умолчанию сервер слушает `0.0.0.0:3000` и может быть доступен по локальному IP компьютера — **учитывайте настройки брандмауэра**. Не открывайте этот порт в интернет с реальными аккаунтами до настройки безопасного сетевого доступа.

Для запуска только на своём компьютере:

**PowerShell:**

```powershell
$env:HOST = '127.0.0.1'
npm start
```

**Linux / macOS:**

```bash
HOST=127.0.0.1 npm start
```

Изменить порт можно через переменную `PORT`, например `PORT=3100 npm start` (Linux/macOS), или `$env:PORT=3100; npm start` (PowerShell).

## Обновление без потери прогресса

1. Остановите старый сервер.
2. Сделайте резервную копию всей папки `data/` и храните её вне папки игры.
3. Распакуйте новую чистую сборку в отдельное место.
4. Перенесите вашу папку `data/` к новому `server.js`.
5. Запустите игру, проверьте вход, постройки, инвентарь и волны.
6. Если обновление прошло неудачно, остановите сервер и восстановите **совместимую резервную копию**.

Не переносите тестовые сохранения и не копируйте пользовательские JSON в публичный репозиторий.

## Потеря соединения и восстановление

Начиная с **Alpha 0.16.0**, браузерная игра после неожиданного разрыва пытается войти заново через сохранённый гостевой токен или действующий сеанс аккаунта. Выполняется не более пяти повторных попыток с увеличивающейся паузой. Ручной выход и ошибки авторизации не запускают бесконечные повторы.

При повторном входе управление и чат сбрасываются, а прогресс загружается из ранее сохранённого профиля. Интервал автоматического сохранения остаётся прежним: при аварийном завершении процесса последние несохранённые изменения могут потеряться. Поэтому для критичных серверов необходимы регулярные резервные копии.

Сервер отключает соединения, от которых долго не поступают пакеты, и освобождает слот и занятый профиль. Игроки с нестабильной сетью могут временно видеть экран переподключения.

## Производительность и мониторинг (Alpha 0.17.0)

Эндпоинт `GET /api/status` показывает обезличенные сведения о состоянии сервера и блок `performance`:

- `uptimeSeconds` — время работы сервера
- `tickAvgMs`, `tickPeakMs` — среднее (сглаженное) и пиковое время игрового тика
- `broadcastAvgMs` — среднее время рассылки игровых состояний
- `snapshotsSent`, `stateBytes` — число и общий размер отправленных игровых снимков с момента запуска
- `skippedBackpressure` — количество пропущенных рассылок медленным клиентам
- `slowDisconnects` — число разрывов за длительную переполненную очередь

Пример для локального компьютера:

```bash
curl http://127.0.0.1:3000/api/status
```

Это диагностические счётчики за текущий запуск, а не постоянная база метрик. Они не содержат ников, паролей, токенов или адресов клиентов.

Чтобы медленный клиент не перегружал память, сервер пропускает новые игровые снимки при накоплении очереди больше 256 КиБ и отключает клиента при непрерывной перегрузке в течение 12 секунд. После освобождения очереди снимки возобновляются; изменения ресурсов будут отправлены заново, если не были доставлены.

Короткая синтетическая проверка нагрузочных сценариев:

```bash
npm run bench:smoke
```

Этот тест **не заменяет** измерение реального сервера с 16 браузерами и нестабильными соединениями.

## Проверки для разработчика

```bash
npm test
npm run build:clean
npm run verify:clean
```

Сборка попадёт в `dist/`; в ней находятся только `START_WINDOWS.bat`, `server.js`, три файла `public/` и пустая `data/`. Документация, тесты, изображения для оформления и реальные сохранения в архив **не включаются**.

## Перед публичным тестированием

- Настройте HTTPS/WSS, контролируемый доступ к серверу и резервное копирование.
- Проверьте защиту регистрации/входа и восстановление аккаунтов.
- Проведите нагрузочные и многопользовательские тесты с реальными браузерами.
- Проверьте логику восстановления мира после падения и повторного запуска.

**До выполнения этих задач VORNIXO не следует считать готовой к открытому релизу.**
